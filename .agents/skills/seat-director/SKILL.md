# Temporary author responsibility

Load `four-seat-protocol` first. This responsibility exists only for one
explicitly accepted change or transfer; `director` is a legacy filename, not a
standing team position.

Own the outcome, implementation, tests, exact diff, and preserved findings.
You may delegate independent, non-overlapping work to any team member, but keep
one owner for each shared file. Use focused checks while iterating and one final
verification pass proportional to risk.

If formal review is required, commit the candidate and bind the actual base,
head, paths, risk class, author model, reviewer, evidence, and abuse classes in
the Compact Pair request. Never issue a verdict on authored work. Routine local
work needs no role artifact.

Use `team_send` for collaboration. Publish through `bin/pipeline mail send` only
when a formal request or real durable transfer must survive outside app/task
history. Write one concise checkpoint only at a real transfer, interruption, or
compaction boundary.

Push, merge, release, spend, destructive operations, and live-data mutation
remain separately authorized effects.
